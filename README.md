# placitum/captcha

Капча Placitum: калитка, которая требует доказать, что клиент — человек, когда на это есть повод.

Один образ, два процесса. Инспектор на шине решает `allow`, `redirect` или `deny`; сервис
виджета показывает проверку и выписывает клиенту куку клиренса. Ключ у них общий, и это
единственное, чем они связаны.

```
модуль ──► waf.req.captcha ──► captcha      ── allow | redirect | deny
                                  │
                                  ├── лестница: профиль, кука клиренса, корзины, просьбы соседей
                                  └── корзины и роастер -- во внутреннем Redis

клиент ──► /waf/captcha ──► captcha-http    ── виджет, проверка ответа, кука waf_clr
```

## Что она умеет

- **Корзины по осям** — адрес, подсеть, система, сессия — на GCRA во внутреннем Redis: один
  писатель на все экземпляры и одна сумма на всех.
- **Провайдеры**: своя картинка или внешние — Turnstile, reCAPTCHA, hCaptcha, SmartCaptcha.
  Провайдер выбирается профилем.
- **Встроенная форма** (`gate.inline`): страница виджета отдаётся телом отказа, без редиректа.
- **Просьбы соседей**: другой инспектор может сообщить капче факт о клиенте, а решает, что с ним
  делать, её профиль.
- **Запись исходов** в активные наборы: клиренс, отказ, бан — адресом, подсетью или системой.

## Сборка и запуск

```sh
docker build -f deploy/Dockerfile -t placitum/captcha .
```

Инспектор — команда по умолчанию, сервис виджета — `captcha-http` на том же образе. Что нужно
рядом, ключи и переменные — [INSTALL.md](INSTALL.md).
